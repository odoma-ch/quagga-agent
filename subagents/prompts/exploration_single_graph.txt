## STRATEGY — follow these steps IN ORDER

Note: This knowledge graph does not use named graphs. Explore it as a single unified graph.

Important: Keep each query's LIMIT small to avoid endpoint timeouts — DO NOT raise the LIMIT values below. To still collect up to ~100 rows per step, you MUST paginate by issuing the SAME query multiple times, keeping LIMIT constant and increasing OFFSET by that LIMIT, until OFFSET reaches 100 (or a page returns 0 rows, whichever comes first).

Within each step, run the pages STRICTLY SEQUENTIALLY: issue ONE tool call, wait for its response, then issue the next page in the next turn. Do NOT batch multiple OFFSET pages into a single message and do NOT issue parallel tool calls. Do NOT re-run the same LIMIT/OFFSET combination. After all pages are collected, merge their rows and de-duplicate before recording.

Step 1 : Get entity types
  Run the following query repeatedly, sequentially (one tool call per turn, waiting for each response before issuing the next; never in parallel).
  OFFSET values, in order: start at 0 and increment by this step's LIMIT (i.e., 0, LIMIT, 2×LIMIT, 3×LIMIT, …) until OFFSET reaches 100; do not exceed OFFSET 100.
  Stop early ONLY if a page returns 0 rows.
  SELECT ?type (COUNT(?s) AS ?count)
  WHERE { ?s a ?type }
  GROUP BY ?type ORDER BY DESC(?count) LIMIT 20 OFFSET <offset>
  Merge rows from all pages and record the combined results.

Step 2 : Get property usage

  WHERE { ?s ?p ?o }

Step 3 : Describe sample entities
  Pick the top 10 entity types from Step 1's results. For EACH of those types, run the following tool calls IN ORDER, one per turn (sequential, never in parallel):
  1. Fetch one sample entity URI for that type:
     SELECT ?s WHERE { ?s a <topType> } LIMIT 1
  2. Count how many outgoing triples that entity has, so we don't pull a huge graph:
     SELECT (COUNT(*) AS ?n) WHERE { <sampleEntityURI> ?p ?o }
  3. Decide based on the count:
     - If ?n <= 200, describe the entity to see its full property profile:
       DESCRIBE <sampleEntityURI>
     - If ?n > 200, the entity is too richly linked; skip DESCRIBE and instead fetch a bounded sample of its properties:
       SELECT ?p ?o WHERE { <sampleEntityURI> ?p ?o } LIMIT 50
  Repeat for each of the top 10 types. If an endpoint does not support DESCRIBE (returns empty or an error), use the same SELECT fallback as above.
  Record all returned triples and use them to characterise what real entities of each top type look like.
